시안 소스를 옮길 때

화면 이미지(목업) · 애니메이션은 시안 HTML 소스를 옮겨 쓰는 것을 기준으로 만들었습니다. 기존 홈페이지 구조에 맞게 고쳐 써도 됩니다. 다만 지금 시안은 아래처럼 짜여 있어서, 고칠 때 이 구조를 놓치면 특정 해상도 · 상태에서만 모양이 틀어지거나 움직임이 빠지기 쉽습니다. 구조를 크게 바꿔야 하면 디자이너와 먼저 공유해 주세요.

  1. 공통 파일 = 여러 페이지가 같이 쓰는 부품assets/common/ 의 wisa.css · badge.css · chart.css · plan.css · wisa.js · chart.js 에 단계 탭 · 단계 카드 · 해결 화면 · 히어로 축소 · 세로 라인 등이 들어 있습니다. 그대로 쓰는 것이 가장 안전하고, 기존 CSS 와 합치거나 나눌 때는 한 규칙이 다른 페이지에서도 쓰인다는 점을 유의합니다. 폰트 경로(fonts/)는 CSS 파일 위치 기준입니다.
  2. 불러오는 순서 = 덮어쓰기 구조CSS: wisa.css → badge.css → chart.css 또는 plan.css → 페이지 <style>. 스크립트: 페이지 <script> 들 → wisa.js → chart.js (모두 </body> 바로 위). 페이지 규칙이 공통 규칙을 덮어쓰는 구조라, 합치거나 묶어 빌드할 때도 이 순서를 유지합니다.
  3. 페이지 <style> = 영역 하나가 해상도 블록 네 곳에 나뉨영역 하나의 스타일이 PC · PC 최소(1024~1439) · 태블릿 · 모바일 블록에 나뉘어 있습니다. 영역별로 나눠 옮기거나 기존 CSS 방식으로 다시 쓸 때는 네 블록과 호버 · 탭 · 동작 줄이기 규칙을 같이 옮겼는지 확인합니다. 지금 화면에 안 걸려 보이는 규칙도 다른 해상도 · 상태에서 씁니다.
  4. 페이지 <script> = 영역별 @region · 공통 값은 같이 씀스크립트는 영역별 @region 으로 나뉘어 있지만, 한 함수 안에서 공통 값(동작 줄이기 · 해상도 · 이미지 경로 등)을 같이 씁니다. 나눠 옮기거나 다른 방식으로 바꿀 때는 이 값을 같이 옮기고, 실행 순서(페이지 스크립트 → 공통 스크립트)를 유지합니다.
  5. 마크업 = CSS · 스크립트가 이름으로 요소를 찾음클래스 · id · data- 속성 · style="--v:.42" 같은 인라인 변수로 모양과 움직임이 연결됩니다. 이름을 바꾸면 CSS · 스크립트의 같은 이름도 함께 바꿉니다. 빈 요소(<i></i> · 말풍선 자리 · 커서)는 자리 · 애니메이션용이라 지우지 않습니다. 이름을 바꾼 곳은 자동 점검에서 '없는 요소'로 나오므로 눈으로 확인합니다.
  6. 화면 이미지 = PC 픽셀 + 비율 축소화면 이미지는 PC 크기(예: 문제 550×300 · 단계 560×480)로 고정해 두고 스크립트가 칸 폭에 맞춰 비율(--s · transform: scale)로 줄입니다. 가로를 % · vw 로 바꾸거나 해상도별로 다시 배치하면 안쪽 글자 · 간격이 틀어집니다 (이미지).
  7. 이미지 · 로고 경로마크업 · CSS 의 assets/... 상대 경로를 서버 경로에 맞게 한 번에 바꿉니다. 일부 화면은 스크립트가 번호로 이미지를 불러옵니다(assets/geo/crm-pf/cp-01~20 · profile/pt-01~10) — 파일 이름을 바꾸지 않습니다.
  8. 헤더 · 푸터는 기존 홈페이지 것시안 헤더 · GNB · 푸터는 확인용 복제입니다. 기존 소스를 쓰고, 메뉴 구성 · 이름 · 링크는 기존 수정 목록 › 마케팅 공통 수정 5번, 그 외 바뀌는 것은 기존 수정 목록대로 고칩니다.
  9. 구현 후 개발 검수다 옮긴 뒤 개발 검수의 자동 점검으로 시안과 비교합니다. 빠진 스타일 · 애니메이션 · 호버가 요소 단위로 나옵니다.
