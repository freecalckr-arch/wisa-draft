비주얼 공통

히어로 · 문제 · 단계 · 해결의 화면 이미지(비주얼)를 그릴 때 지킵니다. 레이아웃은 내용에 맞게 새로 짜도 되고, 색 · 공통 요소 · 크기 단계 · 배치 완성도는 모든 페이지가 같습니다.

실제 목업처럼, 그러나 단순하게

  1. 한 화면 = 메시지 1개처음 2초 안에 "무엇이 좋아졌는지 / 무엇이 문제인지" 하나가 읽혀야 합니다. 그 하나에만 블루 · 큰 숫자 · 애니메이션을 씁니다.
  2. 도식이 아니라 실제 화면 한 장면박스를 화살표로 잇는 흐름도, 큰 아이콘 + 라벨 카드 나열은 PPT 처럼 보입니다. 실제 서비스 화면(관리자 · 앱 · 메신저)의 한 순간을 잘라 보여 줍니다. 실제 로고 · 상품 사진 · 날짜(요일 포함) · 단위가 붙은 수치를 씁니다.
  3. 디테일은 진짜처럼, 양은 적게표 행 3~5개 · 수치 칸 3개 · 그래프 1개 · 버튼 1개 정도. 메시지와 상관없는 메뉴 · 필터 · 아이콘은 지웁니다. 남는 자리는 여백으로 두지 말고 핵심 요소(그래프 · 목록)를 키워 채웁니다.
  4. 애니메이션은 화면당 1개메시지를 보여 주는 움직임 하나(막대가 자람 · 행이 강조됨 · 체크됨). 장면 전체가 바뀌는 교체 애니메이션은 히어로 가운데 창에만 씁니다. prefers-reduced-motion 이면 멈춥니다.

그리기 전에 영역마다 장면 한 줄을 먼저 정합니다: 화면 종류 · 전할 메시지 1개 · 블루 포인트 1곳 · 애니메이션 1개. 예) 해결 ② 정리 — 메신저로 온 데일리 브리핑 · "오늘 할 일 3개가 정리돼 온다" · 1순위 할 일 행 · 할 일이 하나씩 체크.

색 위계 3단계

색이 많으면 무엇이 중요한지 안 보입니다. 화면 대부분은 그레이, 봐야 할 한 곳만 블루입니다. 팔레트(컬러) 밖 헥스값은 만들지 않습니다.

  2. 구분은 색이 아니라 그레이 명도로여러 계열(채널 · 매체 · 등급)은 그린 · 옐로 · 인디고로 나누지 않고 Gray 300 / 400 / 500 단계로, 지금 볼 1개만 블루로 둡니다. 범례 점 색은 그래프 색과 똑같이.
  3. 상태색은 면이 아니라 점 · 글자레드 · 그린을 큰 막대 · 카드 바탕에 칠하지 않습니다. 이슈 카드 한 곳만 바탕 · 테두리를 Error 25~50 / 200 으로.
  4. 쓰지 않는 것장식용 그라데이션 · 점 배경 · 색 이모지 남발 · 진한 색 버튼 여러 개 · 알약 여러 개에 각기 다른 색. 실제 앱을 본뜬 브랜드 고유색은 감싼 요소에 data-brand 와 주석.

문제 영역 비교 화면

  1. 왼쪽(기존) 창은 회색 바탕문제 영역 왼쪽 기존 화면은 창 바탕을 Gray 50 · 테두리 Gray 200 으로 두어 흐리게 보이게 하고, 오른쪽 개선 화면(흰 바탕 · 블루 포인트)이 돋보이게 합니다. 왼쪽 창 안 칩 · 카드처럼 원래 Gray 50 · 100 바탕인 요소는 흰 바탕 + 테두리 Gray 200 으로 바꿔 구분합니다 (GEO .pn.serp · CRM · 리포트 .cr-ms · 공식채널운영 patch-302). 하단 태그 그라데이션은 --ft-bg: var(--gray-50).
  2. 가운데 · 아래 끝에서 20px 위문제 영역 비교 화면의 표시 태그(.me-tag 회색 · .hit-tag 블루)는 화면 박스 가로 가운데, 박스 아래 끝에서 20px 위에 둡니다 (PC 기준 · 축소 시 같은 비율). 태그는 목록 줄 · 칩 안에 넣지 않고 .pn.ows > .ows-ft 줄에 둡니다 (공통 wisa.css why-tag).
  3. 내용과 겹치면 그라데이션태그 자리에 내용이 이어지면 .ows-ft.ov 로 태그를 박스 아래에 겹쳐 띄우고, 태그 뒤에 창 바탕색 그라데이션(위 투명 → 아래 바탕색)을 깔아 내용이 흐려지며 끝나게 합니다 (GEO 문제 영역 기준). 회색 바탕 창은 --ft-bg 로 바탕색을 맞춥니다.

단계(탭 타입) 화면 번호 · 말풍선

단계 영역 탭 타입은 왼쪽 내용(구매 전환 요소 태그)을 이미지 안 번호로 짚고, 탭이 열리면 번호 순서대로 이름 말풍선을 띄웁니다 (.os8-p · 스크립트 onsite-steps · 온사이트 · CRM · 리포트 공통). 이 영역은 레이아웃을 그릴 때부터 말풍선 자리를 같이 잡습니다.

  1. 번호 = 왼쪽 태그 순서이미지 안 번호 1 · 2 · 3 … 은 왼쪽 태그 순서와 같고, 말풍선 문구는 스크립트가 태그 글을 그대로 가져옵니다 (번호 수 = 태그 수). 번호는 짚는 요소의 오른쪽 위 모서리에 붙입니다.
  2. 말풍선 자리를 먼저 비워 둔다말풍선은 오른쪽 우선 → 안 들어가면 왼쪽 → 둘 다 안 되면 번호 아래로 뜹니다 (Gray 900 바탕 · 10.5 / 600 · 높이 약 22). 번호 옆에 말풍선 폭(글자 수 × 약 11 + 16)만큼, 아래로 30 이상 창 안 공간이 남게 번호 위치를 정합니다. 창 머리줄 · 창 아래 끝에 붙은 번호는 아래 · 위로 잘리기 쉬우니 피합니다.
  3. 잘라 내는 칸 안에 번호를 넣지 않는다이미지 칸 · 버튼 · 스크롤 칸처럼 overflow: hidden 인 요소 안 번호는 말풍선이 잘립니다. 그 요소를 overflow: visible 로 두거나, 번호를 바깥 칸에 절대 위치로 둡니다.
  4. 번호끼리 떨어뜨린다말풍선이 다른 번호를 덮지 않게 같은 줄 번호는 말풍선 폭 이상, 위아래 번호는 30 이상 떨어뜨립니다.
  5. 탭마다 모든 번호를 확인점검 스크립트가 탭을 하나씩 열어 번호마다 말풍선 위치(오른쪽 · 왼쪽 · 아래)를 계산해 창 밖 · 잘림 · 번호 겹침을 알려 줍니다. 1440 · 1100 · 390 에서 돌립니다.
  6. 기존 페이지 정리 때 이 영역은 지킨다글자 크기 · 여백을 규격 단계로 맞출 때도 번호가 붙은 요소의 크기 · 위치, .os8-p 위치 · 말풍선 방향 보정(.lf · .dn · 번호별 top/bottom 보정)은 바꾸지 않습니다. 바꿔야 하면 바꾼 탭의 번호 말풍선을 스크립트와 화면으로 다시 확인합니다.

배치 완성도

  1. 창 안 위 · 아래 여백을 같게머리줄 아래 ~ 첫 내용 = 마지막 내용 ~ 창 아래 끝. 내용이 모자라면 위로 쏠리게 두지 말고 세로 가운데 정렬하거나 목록 · 그래프 높이를 늘려 채웁니다.
  2. 한쪽만 비지 않게왼쪽 · 오른쪽 여백도 같게. 한 칸만 텅 비면 칸 비율을 바꾸거나 요소를 키웁니다. 채팅 말풍선처럼 의도한 한쪽 정렬만 예외.
  3. 정렬선은 적게창 안 요소의 왼쪽 시작선은 안쪽 여백 20 하나에 맞춥니다. 같은 종류 요소(행 · 칸 · 카드)는 같은 크기 · 같은 간격으로 반복합니다.
  4. 크기 위계는 3단계큰 숫자/그래프(봐야 할 것) → 제목 · 라벨 → 보조 글자. 같은 크기가 너무 많으면 무엇이 중요한지 안 보입니다.
  5. 겹침 · 잘림 없음글자 · 말풍선 · 라벨이 선이나 다른 글자와 겹치면 빈 공간으로 옮깁니다. 1100 · 390 축소 화면에서도 확인합니다.

그래프 그리기 규칙

그래프 영역(#geo-market) 태블릿 · 모바일 전용 그림을 그릴 때 지킵니다. 세로 길이 · 코드는 그래프 규격 참고.

  1. 전용 그림은 PC 그래프와 같게데이터 · 색 · 애니메이션을 똑같이, 가로가 줄어든 만큼 세로를 확보해 다시 그립니다.
  2. 모바일 글씨 12px 이상단계 이름 12 · 수치 12.5 · 말풍선 11.5.
  3. 말풍선 · 수치는 빈 공간에선이나 다른 글씨와 겹치면 주로 오른쪽 위 빈 공간으로 옮깁니다.

작업 순서

  1. 장면 한 줄영역마다 화면 종류 · 메시지 1개 · 블루 포인트 1곳 · 애니메이션 1개를 정합니다 (기획안 단계 빈 박스 옆에 적어 보여 줌).
  2. 공통 요소로 조립창 · 머리줄 · 칩 · 버튼 · AI · 로고 · 알림은 공통 요소 탭 그대로. 레이아웃만 새로 짭니다.
  3. 점검 스크립트 실행PC 1440 에서 아래 스크립트를 돌리고 나온 항목을 고칩니다. 단계 탭은 탭을 하나씩 열고 다시 돌립니다.
  4. 눈으로 확인1440 · 1100 · 820 · 390 캡처로 메시지가 2초 안에 읽히는지, 색이 그레이 + 블루로 보이는지 봅니다.
