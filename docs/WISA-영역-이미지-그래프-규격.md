## 3. 히어로 — 파란 박스 영역 기준

히어로 안의 구성(폰 · 카드 · 채팅 등)은 페이지마다 다르게 만든다. **규격은 파란 박스(`.sh-visual`) 하나만 고정**하고, 안의 구성은 이 박스 안에 맞춘다.

| 구간 | 박스 가로 | 박스 세로 | 좌우 바깥 여백 | 모서리 | 안쪽 위 여백 |
|---|---|---|---|---|---|
| PC (1440) | 화면 폭 − 100 (1440 → 1340) | **460** | 50 | 24 | 40 |
| PC 최소 (1100) | 화면 폭 − 100 (1100 → 1000) | **460** | 50 | 24 | 40 |
| 태블릿 (820) | 화면 폭 − 100 (820 → 720) | **444** | 50 | 24 | 40 |
| 모바일 (390) | 화면 폭 전체 (390) | **444** | 0 | 0 | 40 (좌우 40) |

- 박스 안 구성은 아래(바닥)에 붙여 배치하고, 넘치는 부분은 박스가 잘라낸다 (`overflow: hidden`).
- 태블릿 · 모바일에서는 박스 양옆에 떠 있는 카드를 숨긴다 (공간 부족).

## 4. 이미지 규칙 (문제 · 단계 · 해결 및 이후 추가되는 모든 화면 이미지)

1. **PC 크기로 한 번만 그린다.** 영역마다 PC 기준 크기(가로×세로)를 정해 그 크기로 만든다.
2. **화면이 좁아지면 비율 그대로 줄인다.**
   - 배율 `s = min(1, 이미지 칸 폭 ÷ PC 가로)`
   - 노출 크기 = PC 가로 × s · PC 세로 × s
   - 레이아웃을 다시 짜거나(줄바꿈 · 칸 수 줄이기), 가로만 늘이거나 줄이지 않는다.
   - 칸이 PC 가로보다 넓으면 확대하지 않고 PC 크기 그대로 둔다.
3. **이미지 안 글씨도 같은 배율로 작아진다.** 따로 키우지 않는다.
4. PC 최소 · 태블릿 · 모바일 모두 같은 규칙.

### 영역별 PC 기준 크기 (온사이트마케팅 기준 · 다른 페이지는 같은 칸이면 같은 크기 사용)

| 영역 | 이미지 | PC 기준 가로×세로 | 모바일 390 노출 (s) |
|---|---|---|---|
| 문제 | 화면 이미지 (카드마다 1개) | **551×300** | 289×157 (0.52) |
| 단계 | 단계 화면 이미지 (탭마다 1개) | **560×483** | 283×244 (0.51) |
| 해결 | 단계 줄 화면 이미지 (줄마다 1개) | **460×380** | 283×234 (0.62) |
| 리포트 | 대시보드 전체 | 1240×623 | 모바일 전용 배치 (PC 최소는 비율 축소) |
| 사례 | 사례 사진 | 393×210 | 칸 폭에 맞춰 잘라 채움 (사진이라 예외) |

### 구현 (그대로 복사해서 사용)

```css
/* 이미지 칸(.vis) 안에 PC 크기 이미지(.win)를 그리고 배율 --s 로 축소 */
@media (max-width: 1439px) {
  .vis { position: relative; overflow: visible; height: calc(PC세로px * var(--s, 1)); }
  .vis > .win { width: PC가로px; height: PC세로px; max-width: none; transform-origin: 0 0; transform: scale(var(--s, 1)); }
}
```

```js
// 칸 폭이 바뀔 때마다(숨겨진 탭이 열릴 때 포함) 배율 다시 계산
const list = [[document.querySelectorAll('#geo-why .bt-vis'), 551], [document.querySelectorAll('#geo-how .jt-panel .sc'), 560], [document.querySelectorAll('#geo-diagnosis .sr-vis'), 460]];
const ro = new ResizeObserver(es => es.forEach(e => { const v = e.target; if (v.clientWidth) v.style.setProperty('--s', Math.min(1, v.clientWidth / v.dataset.pcw).toFixed(4)); }));
list.forEach(([els, w]) => els.forEach(v => { v.dataset.pcw = w; ro.observe(v); }));
```

## 5. 그래프 규칙 — 해상도별 세로 길이

### 그래프 영역 (`#geo-market` 메인 그래프)

| 구간 | 그래프 세로 | 그림 |
|---|---|---|
| PC (1440) | 폭 × 250/920 (1440 → **319**) | PC용 (viewBox 920×250) |
| PC 최소 (1100) | 폭 × 250/920 (1100 → **250**) | PC용 |
| 태블릿 | **220 고정** | 태블릿 전용 (viewBox 640×220) |
| 모바일 | **210 고정** | 모바일 전용 (viewBox 298×210) |

- 태블릿 · 모바일 전용 그림은 PC 그래프와 **데이터 · 색 · 애니메이션을 똑같이** 두고, 가로를 줄인 대신 세로를 확보해 다시 그린다.
- 글씨: 모바일 12px 이상 (단계 이름 12 · 수치 12.5 · 말풍선 11.5).
- 말풍선 · 수치 글씨가 선이나 다른 글씨와 겹치지 않게 빈 공간(주로 오른쪽 위)에 둔다.

### 리포트 그래프

| 그래프 | PC | PC 최소 | 태블릿 | 모바일 |
|---|---|---|---|---|
| 일별 구매 전환율 | 104 | 83 (대시보드 비율 축소) | 숨김 | 104 |
| 도넛 | 112 | 89 | 숨김 | 숨김 |

### 이미지 안 그래프

해결 · 적용 꺾은선처럼 화면 이미지 안에 있는 그래프는 따로 정하지 않고 **이미지 배율을 따른다.**
