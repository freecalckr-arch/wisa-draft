작업 순서

  1. 받기이 PC 에서는 위 PC 폴더에서 작업 전마다 git pull. 다른 PC 에서는 처음 한 번 git clone https://github.com/freecalckr-arch/wisa-draft.git 후 같은 방법으로.
  2. 고치기해당 페이지 HTML 을 고치고, 이 사이트의 규칙을 따릅니다.
  3. 기록HTML 맨 위 [개발 전달] 주석과 바뀐 CSS 의 patch-NNN 주석에 수정 내용을 남깁니다.
  4. 확인1440 · 1100 · 820 · 390 에서 보고, 모바일에서 페이지가 옆으로 밀리지 않는지 봅니다.
  5. 올리기git add → git commit → git push. 1~2분 뒤 시안 보기 주소에 반영됩니다.

자사몰 마케팅 디자인 작업 순서

새 페이지(CRM · 리포트 등)나 큰 수정은 아래 순서대로 진행합니다. 재구성이 끝나기 전에 비주얼부터 그리지 않습니다.

  1. 기획문서 확인기획문서에서 해당 페이지의 문장 · 흐름 · 레이아웃을 확인합니다.
  2. 내용 · 사이즈 재구성기획문서의 문장 · 흐름 · 레이아웃을 디자인 완료 페이지(GEO · 온사이트) 규격에 맞게 다시 짭니다. 영역 이름 · 순서는 영역 이름, 이미지 · 그래프 크기는 이미지 · 그래프, 히어로는 히어로 규격을 따릅니다.
  3. 비주얼 디자인재구성한 틀 위에 화면 이미지 · 애니메이션을 그립니다. 색은 컬러, 글자는 타이포 규격 안에서만 씁니다.

자사몰 마케팅 디자인 지침

  1. 히어로 카피특정 키워드만 바뀌는 교체 애니메이션을 적용할 수 있게 문구를 다듬습니다. 바뀌는 키워드는 한 자리에 두고, 앞뒤 문장은 어떤 키워드가 들어가도 자연스럽게 읽히게 씁니다 (예: GEO "[ChatGPT]가 / 우리 브랜드와 상품을 / 추천하도록 만듭니다" → [ ] 자리만 ChatGPT · Gemini · Claude 로 교체).
  2. 비주얼 이미지화면 이미지를 만들 때 레이아웃과 타이포 배치에 신경 씁니다. 정렬선을 맞추고, 제목 · 수치 · 설명의 크기 위계를 분명히 하고, 요소 사이 여백을 일정하게 둡니다. 글자가 이미지 · 다른 요소와 겹치거나 잘리지 않게 확인합니다.

시안 히스토리

각 시안 왼쪽 아래 "시안 히스토리"(#vh 의 data-items)에는 고객에게 공유한 시안만 남깁니다. 혼자 작업한 중간 과정은 넣지 않고, 같은 차수가 여러 번 고쳐졌으면 최종 1개만 둡니다. 지금 보고 있는 시안은 "지금 보는 시안"으로 표시합니다 ("current": true).

이름 표기

페이지명 · 버전 · 타입 (같은 버전이 2개 이상일 때만) · 해상도
예시설명
GEO · 1차 시안 · A타입 · PC같은 차수에 A · B 두 안이 있어 타입 표기
GEO · 수정시안 · PC한 안이라 타입 없음
GEO · 반응형 시안(PC/TB/MO)해상도가 여럿이면 괄호에 PC/TB/MO

이 네 가지 외의 내용(수정한 영역 이름, 작업 내용 등)은 이름에 넣지 않습니다.

{"date":"2026.11.06","name":"GEO · 반응형 시안(PC/TB/MO)","url":"geo.html"},
{"date":"2026.11.07","name":"온사이트마케팅 · 1차 시안(PC/TB/MO)","current":true}

마지막 수정 2026-11-07 · 규칙이 바뀌면 이 페이지를 먼저 고치고, 각 시안 HTML 맨 위 [개발 전달] 주석도 같이 맞춥니다.
