자사몰 마케팅 디자인 작업 순서

새 페이지(CRM · 리포트 등)나 큰 수정은 아래 순서대로 진행합니다. 재구성이 끝나기 전에 비주얼부터 그리지 않습니다.

  1. 기획문서 확인기획문서에서 해당 페이지의 문장 · 흐름 · 레이아웃을 확인합니다.
  2. 내용 · 사이즈 재구성기획문서의 문장 · 흐름 · 레이아웃을 디자인 완료 페이지(GEO · 온사이트) 규격에 맞게 다시 짭니다. 영역 이름 · 순서는 영역 이름, 이미지 · 그래프 크기는 이미지 · 그래프, 히어로는 히어로 규격을 따릅니다.
  3. 비주얼 디자인재구성한 틀 위에 화면 이미지 · 애니메이션을 그립니다. 색은 컬러, 글자는 타이포 규격 안에서만 씁니다.

자사몰 마케팅 디자인 지침

  1. 히어로 카피특정 키워드만 바뀌는 교체 애니메이션을 적용할 수 있게 문구를 다듬습니다. 바뀌는 키워드는 한 자리에 두고, 앞뒤 문장은 어떤 키워드가 들어가도 자연스럽게 읽히게 씁니다 (예: GEO "[ChatGPT]가 / 우리 브랜드와 상품을 / 추천하도록 만듭니다" → [ ] 자리만 ChatGPT · Gemini · Claude 로 교체).
  2. 단계 영역 타이틀단계 영역(#geo-how) 제목은 단계 이름이나 개수("여섯 단계")를 앞세우지 않고, 무엇을 파악해서 어떻게 개선하는지를 씁니다 (예: 온사이트 "고객이 어디서 망설이고 떠나는지 찾아 구매를 막는 지점을 고칩니다" · CRM "다시 살 때와 멀어질 때를 파악해 맞는 메시지를 먼저 보냅니다").
  3. 단계 말풍선 문구기획문서를 재구성할 때 단계 영역(#geo-how) 프로필 옆 말풍선은 고민 · 불만이 아니라, 그 단계를 개선한 뒤 고객이 하는 긍정적인 반응으로 씁니다 (예: 온사이트 안심 "교환 무료라 부담 없이 사요" · CRM 재구매 "딱 떨어질 때 알려줘서 편하다"). 문구를 바꿀 때는 채팅으로 바뀔 문구를 먼저 보여준 뒤 확정본을 적용합니다.
  4. 히어로 주변 요소 움직임히어로 박스 안에 떠 있는 카드 · 토스트 · 이미지는 모두 같은 둥둥 애니메이션(위아래 8px · 6초)을 씁니다. 자세한 규격은 히어로 참고.
  5. 비주얼 이미지화면 이미지를 만들 때 레이아웃과 타이포 배치에 신경 씁니다. 정렬선을 맞추고, 제목 · 수치 · 설명의 크기 위계를 분명히 하고, 요소 사이 여백을 일정하게 둡니다. 글자가 이미지 · 다른 요소와 겹치거나 잘리지 않게 확인합니다.

공통 파일 고치는 법

파일 구조와 공통 파일이 담는 내용은 산출물 · 파일 구조에 있습니다. 그 밖에 저장소에는 CLAUDE.md(Claude 가 작업 시작 때 읽는 요약 규칙)가 있고, 새 이미지는 assets/geo/… 아래에 넣습니다. 공통 파일은 wisa.css 를 <head> 의 첫 <style> 바로 위, wisa.js 를 </body> 바로 위(페이지 스크립트 다음)에서 불러옵니다 (patch-172).

  1. 새 페이지GEO 또는 온사이트를 복사해 시작하고, wisa.css · wisa.js 연결은 그대로 둡니다. 페이지 전용 CSS · 스크립트만 HTML 안에 씁니다.
  2. 페이지 전용 수정HTML 의 <style> 에 씁니다. 공통 파일보다 뒤에 오므로 공통 규칙을 덮어씁니다.
  3. 공통 수정모든 페이지에 똑같이 들어가야 하는 수정은 wisa.css · wisa.js 에서 합니다. 고친 뒤에는 이 파일을 쓰는 모든 페이지의 ?v= 숫자를 새 patch 번호로 올립니다 (브라우저가 이전 파일을 저장해 두고 쓰지 않게).
  4. 공통으로 옮기기페이지 전용 코드가 2개 이상 페이지에 똑같이 생기면 공통 파일로 옮깁니다. 옮기기 전후로 화면이 같은지 확인합니다.
  5. 경로wisa.css 안의 이미지 · 폰트 경로는 CSS 파일 위치 기준입니다 (예: url("fonts/…") = assets/common/fonts/…).

헤더 · GNB · 푸터 등의 스크립트는 아직 각 페이지의 큰 스크립트 안에 페이지 전용 코드와 섞여 있어 분리하지 않았습니다. 마크업(HTML)도 페이지마다 그대로 둡니다.

시안 히스토리

각 시안 왼쪽 아래 "시안 히스토리"(#vh 의 data-items)에는 고객에게 공유한 시안만 남깁니다. 혼자 작업한 중간 과정은 넣지 않고, 같은 차수가 여러 번 고쳐졌으면 최종 1개만 둡니다. 지금 보고 있는 시안은 "현재 시안"으로 표시합니다 ("current": true).

날짜 표기

날짜는 고객에게 공유한 날로 적고, 날짜 옆에는 항상 요일을 표기합니다. data-items 에는 "date":"2026.11.08" 처럼 날짜만 적으면 공통 wisa.js 가 요일을 계산해 붙입니다.

규격 페이지 추가하기

  1. docs/ 에 있는 페이지 하나를 복사해 새 이름으로 저장합니다 (예: docs/tab.html).
  2. 제목 · 설명 · 본문을 고칩니다. 탭이 필요하면 <section class="panel" data-tab="이름"> 으로 나눕니다. 맨 위 분류 표시(.eyebrow)는 개발 전달 또는 디자인 중 어디에 속하는지 적습니다.
  3. docs/assets/docs.js 맨 위 NAV 에서 개발자가 구현할 규격이면 { part: "개발 전달" } 아래, 시안을 그릴 때만 쓰는 규칙이면 { part: "디자인" } 아래 분류에 한 줄 추가하거나 null 을 파일 이름으로 바꿉니다.
